# virtual-machine
バイナリデータを扱うCPUが作りたい

# 仕様

動作環境:Windows (11)  
必要ライブラリ:`pygame-ce`  

## 基本

**レジスタはA~Dの4本。**  
**メモリは0x0000~0xFFFFの16bit、65536個。**  
***スタックはメモリの0xFFFFから2バイトずつ(上位→下位の順)で積む***  
**計算処理のたびにゼロフラグ、キャリーフラグが更新される。**  

## つかいかた

**基本的に、main.pyを起動してbiosを経由、os.sema3を読み込む。**

### OSの操作

`ENTER>`　の先にコマンドを打ち込む(大文字小文字を区別する)。

***コマンド集:***
| コマンド | 効果 |
|---|---|
|exit|OSを終了する。|
|file|打ち込んだファイル名のファイルをdataフォルダから読み込んで実行する。|
|color|描画テストをする。|

ファイルは原則0x2000に読み込む。(プログラムを書くとき、OSから起動する前提のファイルは、.org 0x2000などで、ロード位置を0x2000に指定すること。)  

描画テストはwasdで操作して、1234で色を変えて、0で終了。  

たまに反応しないことがあるので、その場合は打ち直し。  

## ヘッダー

専用の拡張子の `.sema3` は、ヘッダーに  
**ThisIsOh**(**8 byte**)  + バージョン番号(**1 byte**) + ロード位置アドレス(**2 byte**) + 開始位置アドレス(**2 byte**)  
の**13 byte**をつける。

#### キー入力デバイス
**キー入力をリアルタイムで受け取るデバイス(0x09,0x0A,0x0B,0x0C)。**  
スロットに設定されたキー入力をビットで返す。  

`read_held`(0x09)は入力されていれば１、されていなければ０を返す。  
`read_edge`(0x0A)は入力された瞬間に１、それ以外で０を返す。  
`set_slot `(0x0B)でスロットを指定して、  
`set_key  `(0x0C)でキーの番号をセットする。  

初期状態ではスロット指定は0、スロットの中身は以下のようになっている。  
**[0x26, 0x28, 0x25, 0x27, 0x5A, 0x58, 0x43, 0x56]**  
  **↑     ↓     ←     →     Z     X     C     V**  

***ビットの見た目とリストの順番が逆になっていることに注意。***  
*左から順に1,2,4,8,16,32,64,128になっている。*  

例:
上のスロットで、`↑  ↓  z`　を入力した場合、  
帰ってくる値は`0x13`(0b**00010011**,**19**)。  

## サウンドデバイス
`sounddevice`で音源を扱うデバイス(0x0C,0x0D)。
`snd_sel(0x0C)`は、送った値の上位の2ビットからチャンネルを指定する (0b**00**000000)。  
*00,01,10,11で4チャンネル*指定でき、下位の6ビットで
機能を指定する。  
| 番号 | 機能 |
|---|---|
| 0 | 音程を指定する。 |
| 1 | 音色を指定する(0x00~0x03)。 |

`snd_val(0x0D)`は、`snd_sel`で指定したところに、`snd_val`に送られた値を入れる。音程や音色を指定するのはここ。

## 通信デバイス
外部とやりとりするデバイス(0x12~0x1C)。

#### 使い方

***基本情報***  

通信すると、1バイトずつ受信/送信ができる。    
N.portset(`0x15`,OUT)で自分のポートを設定する。1バイトずつ送信されて、最大2バイト、65536通りのポートが設定できる。省略すると5000。  


***通信を仕掛ける側***  

まず、N.nameout(`0x12`,OUT)で1バイトずつ送信先を指定する。  
最後にN.nameoutに`0x00`を送ることで通信を開始できる。
ascii文字で、**"example.com"**や **"127.0.0.1"**などと送信する。  
N.recving(`0x12`,IN)やN.status(`0x14`,IN)で通信の状態を取得できる。  
*recving(0=今は読むデータがない 1=読める)*  
*status(0=未接続 1=接続中 2=切断された)*  
そうしたら、N.rx(`0x13`,IN)で、通信先のデータを1バイトずつ受け取ることができる。  

***通信を仕掛けられる側***

N.ipset(`0x19`,OUT)でどのローカルIPアドレスで待ち受けるかを指定する。1バイトずつ送信されて、4回送信して`"n1.n2.n3.n4"`の形にする。  
N.listen_start(`0x17`OUT)で接続を待つ。IPが正しく設定されていない場合、**"127.0.0.1"**(自分のPC内のみ)になる。  
N.accepting(`0x17`,IN)で人がいるかどうか確認できる。  
*accepting(0=来ていない 1=来ている)*  
N.listen_stop(`0x18`,OUT)で通信を待つのをやめる。   

***接続後***  

N.sendcharge(`0x13`,OUT)で1バイトずつデータを貯める。  
N.send(`0x14`,OUT)で貯めたデータを送信する。HTTPリクエストを送る場合、これを使う。  

接続は、番号(0から)で管理される。rx、recving、status、send、sendcharge、closeは、**今選んでいる接続**に対して働く。  
N.select(`0x1B`,OUT)で番号を選び、N.count(`0x1B`,IN)で今の人数を調べることができる(255を超えるとオーバーフローする)。  
範囲外の場合未選択になる。  
N.close(`0x16`,OUT)で切ると、選択中の番号の人の接続が切れて、後ろの人の番号が1つ詰まる。  

### 想定メモリマップ
0x0000 ~ 0x00FF  
ブートローダー、BIOS  

0x0100 ~ 0x1FFF  
OS  

0x2000 ~ 0x7FFF  
ユーザープログラム領域  
 
0x8000 ~ 0x9FFF  
変数  

0xA000 ~ 0xEFFF  
VRAM領域(E000以降は予備)  

0xF000 ~ 0xFFFF  
スタック領域  



# 命令集
### 記号
- `n`：即値。`0x00` ～ `0xFF` の範囲の値を指定する。  
- `r`：レジスタ番号。`0x00` ～ `0x03` を指定し、それぞれ A、B、C、D レジスタに対応する。  
- `a`：アドレスを表す2バイトの値。リトルエンディアン方式で格納される。  
  
| オペコード | 命令 | 説明 | サイズ | 構文 |
|---|---|---|---|---|
| `0x00` | `NOP` | 何もしない。| 1 byte | `NOP` |
| `0x01` | `LOAD` | 即値をレジスタに書き込む。| 3 bytes | `LOAD r, n` |
| `0x02` | `ADD` | 即値をレジスタに足す。| 3 bytes | `ADD r, n` |
| `0x03` | `SUB` | 即値をレジスタから引く。| 3 bytes | `SUB r, n` |
| `0x04` | `LOADM` | 指定アドレスの値を指定レジスタに書き込む。 | 4 bytes | `LOADM r, a` |
| `0x05` | `STOREM` | 指定アドレスに指定レジスタの値を書き込む。 | 4 bytes | `STOREM r, a` |
